refactor-gate | Implement the gated refactor stage per SPEC.md section 3.2 — the one human checkpoint in the whole pipeline, so it must be conservative. For each COLLIDING-SPLITTABLE group in plan.json, generate a refactor PLAN ONLY via one headless call on PLANNER_MODEL: which files split, into what, what moves where, and why that makes the colliding tasks disjoint. Print it and STOP for stdin approval — approve/reject only; `edit` is deferred (SPEC.md section 9). Default to reject on empty input or EOF, exactly as the base-branch confirmation in seed.sh does. Only on approval execute it: a headless agent on PLANNER_MODEL performs the refactor in its own worktree cut from BASE_BRANCH, behavior-preserving changes only, then the full suite runs there. On green, BASE_BRANCH advances by exactly that refactor commit (fast-forward; the run holds the base so it cannot have moved) — this is the ONE place the tool ever writes to the base branch, permitted by SPEC.md section 3.2 precisely because a human approved it and the suite is green. On red: discard the worktree, leave BASE_BRANCH untouched, report. Never weaken or edit an existing test to make it pass. Never fan out on a red baseline. The plan-generation and refactor-execution invocations must each be distinguishable in tests/fake-claude (marker in prompt, own FAKE_CLAUDE_*_MODE), as the probe and planner already are — no existing test may change. Ship with tests covering approve, reject, EOF-defaults-to-reject, the red-suite path proving BASE_BRANCH is byte-identical afterwards, and the green path proving BASE_BRANCH advanced by exactly one commit.
run-wiring | Wire the Stage 3 pipeline into `run` so it executes SPEC.md section 3 end to end: (1) conflict detection via lib/plan.sh writes plan.json into the run dir; (2) the refactor gate runs for every COLLIDING-SPLITTABLE group and stops for approval — a rejection or a red refactor aborts the run before any task worktree is cut, never fanning out on a red baseline; (3) DISJOINT tasks fan out in parallel via lib/fanout.sh, with lane checks at their gates; (4) INHERENTLY-COUPLED groups run via the coupled-serial scheduler; (5) the fan-in report. Add a --no-plan flag that skips steps 1 and 2 and treats every task as DISJOINT — the Stage 2 behavior, for a human who wrote the backlog to be disjoint and does not want to pay for a planner call — and print a loud one-line notice in the run header when it is used. run-one is unchanged: a single task has nothing to collide with. Ship with tests proving the ordering (plan before refactor before fan-out), that a rejected refactor aborts before any task worktree exists, and that --no-plan never invokes the planner.
