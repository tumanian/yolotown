task-core | Extract the duplicated task-execution core into lib/task.sh, so there is exactly one implementation. Today seed.sh and the yt_run_task function inside the yolotown entrypoint are two copies of the same pipeline — worktree from BASE_BRANCH, copy and verify ENV_FILES, build the worker prompt, run the agent, gate on TEST_CMD, commit, push if PUSH_ON_GREEN — and they have ALREADY diverged: yolotown's copy passes </dev/null to the agent, seed.sh's does not, so `yolotown run` does not stall on stdin but `yolotown run-one` does. The new function must be parameterized by run dir and task name (it must NOT create its own run dir — the caller owns that, because `run` puts a whole batch in one run dir) and must RETURN 0/1 rather than exit, so a batch can continue past a failure. seed.sh becomes a thin wrapper that creates a run dir, registers its one task, and calls it; yt_run_task becomes a thin wrapper that passes in the shared run dir. Unify the stdin handling on the </dev/null form — that is a deliberate, documented behavior change for seed.sh (it stops stalling ~3s per dispatch), so note it in the commit rather than smuggling it in. This is a REFACTOR: behavior-preserving apart from that one documented change, the full suite must stay green, and per SPEC.md section 4 you must never weaken, delete, or edit an existing test to make it pass. If an existing test genuinely must change because an interface moved, say so explicitly and keep its coverage at least as strong. Ship with tests for the new library.
agent-stdin | Redirect stdin on seed.sh's headless agent invocation. NOTE: if task-core lands first and unifies both call sites on </dev/null, the fix itself is already done and this task reduces to shipping the regression test described below — verify before starting, and say so rather than inventing work. Today the `"$CLAUDE_BIN" -p "$PROMPT" ... --allowedTools ...` call inherits the caller's stdin, so every real dispatch stalls ~3 seconds and writes 'Warning: no stdin data received in 3s, proceeding without it' into the run log. Fix: add `</dev/null` to that command. It is safe — seed.sh's only interactive prompt (the missing-BASE_BRANCH y/N confirmation) runs in preflight, well before the agent. This MUST land before fan-out, where N parallel workers would otherwise all inherit and race on the same stdin. The test is the hard part: tests/helpers.sh's run_seed already redirects stdin from /dev/null, so the mocked suite structurally cannot observe the bug — a passing test written naively would prove nothing. Write a test that runs seed.sh with stdin connected to a PIPE CARRYING DATA and has tests/fake-claude record whether it could read that data; without the fix the shim sees the data, with it the shim sees EOF. Ship with that test.
fan-out | Implement bounded parallel workers via subshells honoring MAX_PARALLEL (with a --parallel N override and a --serial fallback), per-worker status files via lib/rundir.sh, and crash containment (one worker's crash never kills the run), followed by the fan-in report. See SPEC.md section 3.3. Tests must prove the concurrency bound using shim sleeps. Ship with tests.
