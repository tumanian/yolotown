refactor-edit | Add the deferred `edit` option to the refactor gate's approval prompt (SPEC.md section 3.2 lists approve / reject / edit; section 9 records edit as deferred, read today as a rejection). Decide and document the semantics before implementing: the simplest faithful reading is that `edit` opens the printed refactor plan in $EDITOR, re-prints the edited plan, and asks again — so the human amends the plan rather than the code, and every other rule of the gate (explicit yes only, EOF rejects, behavior-preserving execution, green-or-discard) is unchanged. Remove the section 9 entry when done. Ship with tests covering an edited-then-approved plan reaching the refactor agent verbatim, and an edited-then-rejected one changing nothing.
agent-timeout | Bound how long a single agent may run, so a hang becomes a normal failure instead of an unbounded one. Today there is no timeout at all (recorded as out-of-seed-scope in DESIGN.md at Stage 0 and never picked up): a wedged agent holds its worker slot forever, and at MAX_PARALLEL 3 that permanently costs a third of the throughput. Add an AGENT_TIMEOUT config key to lib/config.sh — seconds, default 0 meaning no limit so existing behavior is the default, validated like MAX_PARALLEL (a non-numeric or negative value is refused, not rounded). Enforce it in lib/task.sh around the single CLAUDE_BIN invocation, which is the only agent call site since task-core unified them. GNU timeout(1) is NOT available on macOS and is not one of the assumed binaries (SPEC.md section 4: git, node and the claude CLI only), so implement the watchdog in bash — background the agent, poll for its completion up to the deadline, then kill the process GROUP so a killed agent leaves no orphaned child, and reap it. A timed-out task is FAILED with reason "timed out after <n>s", its worktree left intact for autopsy exactly like any other failure, and its slot freed so the rest of the run proceeds. The refactor gate's execution call (lib/refactor.sh) should honor the same bound. Ship with tests using a shim mode that sleeps past a short timeout, proving: the task is FAILED not hung, the reason names the timeout, the worktree survives, sibling tasks still run, and AGENT_TIMEOUT=0 never interrupts a slow-but-finishing agent.
status-heartbeat | Show how long a task has been in its current state, so a wedged run is visible at a glance. Today `yolotown status` prints RUNNING with no indication whether that started two minutes or two hours ago, and the status file carries no timestamp — the only in-band clue is the file's own mtime, which lib/rundir.sh already updates on every yt_status_set. Read that mtime in lib/report.sh and render an elapsed column, so a row reads e.g. "RUNNING pdf-selection-offset 42m log=… worktree=…". Do NOT change the status file format: it stays one word, the state machine and its enforced transitions are untouched, and nothing about yt_status_get/yt_status_set changes — this is a presentation-only change to the report. Show elapsed for every state, since "FAILED 3d" is also useful when reading an old run dir. Keep it stable across platforms: stat(1) flags differ between macOS and Linux, so derive the mtime portably (a small node one-liner is allowed and is how this repo does that kind of thing). Ship with tests that set a known mtime on a status file and assert the rendered elapsed string, including a just-now case and a multi-day case.
