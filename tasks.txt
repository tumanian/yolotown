agent-stdin | Redirect stdin on seed.sh's headless agent invocation. Today the `"$CLAUDE_BIN" -p "$PROMPT" ... --allowedTools ...` call inherits the caller's stdin, so every real dispatch stalls ~3 seconds and writes 'Warning: no stdin data received in 3s, proceeding without it' into the run log. Fix: add `</dev/null` to that command. It is safe — seed.sh's only interactive prompt (the missing-BASE_BRANCH y/N confirmation) runs in preflight, well before the agent. This MUST land before fan-out, where N parallel workers would otherwise all inherit and race on the same stdin. The test is the hard part: tests/helpers.sh's run_seed already redirects stdin from /dev/null, so the mocked suite structurally cannot observe the bug — a passing test written naively would prove nothing. Write a test that runs seed.sh with stdin connected to a PIPE CARRYING DATA and has tests/fake-claude record whether it could read that data; without the fix the shim sees the data, with it the shim sees EOF. Ship with that test.
fan-out | Implement bounded parallel workers via subshells honoring MAX_PARALLEL (with a --parallel N override and a --serial fallback), per-worker status files via lib/rundir.sh, and crash containment (one worker's crash never kills the run), followed by the fan-in report. See SPEC.md section 3.3. Tests must prove the concurrency bound using shim sleeps. Ship with tests.
